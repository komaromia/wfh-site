# WFH website

This directory is the source of the public WFH website. It is deployed from a **separate public repo**, `komaromia/wfh-site` (same setup as `kjournal-site` and `kdocu-site`), so this app repo can stay private.

- Home: https://komaromia.github.io/wfh-site/
- Workout builder: https://komaromia.github.io/wfh-site/builder.html
- Privacy policy: https://komaromia.github.io/wfh-site/privacy.html
- Support: https://komaromia.github.io/wfh-site/support.html
- Terms: https://komaromia.github.io/wfh-site/terms.html

The app uses these through `AppLinks`. App Store Connect needs the Privacy Policy and Support URLs.

Publishing: edit files here, then run `tools/publish-site.sh` (mirrors `site/` to the root of the site repo, commits, pushes). Pages serves `main` at `/`; `.nojekyll` keeps files served as-is. No GitHub Actions workflow.

Fonts: Barlow and Barlow Condensed (SIL OFL, see `fonts/OFL-Barlow.txt`) are self-hosted so the pages load nothing from third parties. Colours follow `docs/DESIGN.md` §3. `icon.png` is the app icon, generated by `tools/make-icon.swift`.

`builder.html` and `workout-builder.js` generate and read version 1 `.kworkout` files entirely in the browser. Keep their field names and limits aligned with `KWorkout/Domain/WorkoutFile.swift`.

`catalog.js` is the exercise list the builder offers (852 exercises: id, name, equipment, muscles, movement, per-side / timed flags). It is generated from `KWorkout/Domain/Catalog.swift` and `KWorkout/Resources/Catalog/catalog.json` by `tools/site/build_catalog.py`; rerun that after catalog changes. Picked exercises are written to the file by catalog ID, so the app resolves them itself; custom ones travel with their own definition.

**Share links.** The builder's *Share link* makes `open.html#<payload>`, where the payload is `z.` + base64url of the raw-deflated workout JSON (`j.` + plain base64url when the browser has no CompressionStream). `open.html` (with `open-workout.js`) decodes it in the browser, shows the workout, and offers *Open in WFH* (`kworkout://import?d=<payload>`, handled by `AppModel.open` / `WorkoutFile.decode(linkPayload:)`), *Save file* and *Edit in the workout builder*. Nothing is uploaded: the workout lives in the URL fragment, which is never sent to the server. This exists because iMessage does not hand custom-type attachments to the app when tapped.

**Landing page.** `index.html` (English) uses `landing.css` and `landing.js` on top of `style.css`; the translated home pages only use `style.css`. `img/*.webp` are 560 px-wide copies of `AppStore/final-raw/*.png` (made with `cwebp -q 80 -resize 560 0`); retake them there when the app UI changes. The "Try it" generator on the page picks from `catalog.js` (the app's real exercise list) and hands its result to the builder as a share-link payload.
